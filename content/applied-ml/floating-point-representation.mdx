<TLDR>
Floating point numbers approximate real numbers with fixed bits. They have limited range, limited precision, and rounding error.
</TLDR>

## Core idea

A floating point number stores three parts:

| Part | Purpose |
|---|---|
| sign | stores positive or negative sign |
| exponent | stores scale |
| significand | stores significant bits |

A simplified value has the form:

$$
(-1)^{s} \times 1.m \times 2^{e}.
$$

The exponent controls range.

The significand controls precision.

## Common formats

| Format | Bits | Notes |
|---|---:|---|
| fp32 | 32 | common training and optimizer format |
| fp16 | 16 | fast but small exponent range |
| bf16 | 16 | fp32-like exponent range with fewer significand bits |
| fp64 | 64 | high precision but slower on many accelerators |

<a href="/learn/applied-ml/mixed-precision-training">Mixed Precision Training</a> uses these formats together.

## Rounding and non-associativity

Floating point addition is not always associative.

Usually:

$$
(a+b)+c \ne a+(b+c).
$$

This happens because each operation rounds.

Parallel reductions can change summation order.

Thus, distributed runs can produce small numeric differences.

## Overflow and underflow

Overflow occurs when a value exceeds the maximum finite value.

Underflow occurs when a value becomes too close to zero.

These failures often appear in exponentials, divisions, and low-precision gradients.

Use <a href="/learn/applied-ml/numerical-precision-tricks">Numerical Precision Tricks</a> to reduce risk.

## Code example

```python
import numpy as np

a = np.float32(1e20)
b = np.float32(-1e20)
c = np.float32(3.14)

print((a + b) + c)
print(a + (b + c))
```

## Common mistakes

Do not assume floating point math equals real-number math.

Do not assume exact reproducibility across devices.

Do not compare floats with exact equality unless values are controlled.
