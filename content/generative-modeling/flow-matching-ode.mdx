<TLDR>
Flow matching learns a continuous vector field for an ODE. Sampling starts from simple noise and follows the learned flow to the data distribution.
</TLDR>

## Core idea

Flow matching defines a time-dependent ODE:

$$
\frac{dx}{dt}=v_\theta(x,t).
$$

The vector field $v_\theta$ moves samples through time.

A common convention uses:

$$
x_0 \sim p_{\text{base}},
\quad
x_1 \sim p_{\text{data}}.
$$

Sampling starts from the base distribution at $t=0$.

Then an ODE solver moves the sample to $t=1$.

This differs from <a href="/learn/generative-modeling/diffusion-reverse-process">diffusion sampling</a>, which often uses stochastic reverse steps.

## Probability path

Flow matching chooses a probability path $p_t$ between base noise and data.

The vector field should transport this path.

It must satisfy the continuity equation:

$$
\partial_t p_t(x)
+
\nabla\cdot(p_t(x)v_t(x))
=
0.
$$

This equation states conservation of probability mass.

The model learns $v_t$ without direct density evaluation.

## Conditional flow matching

A simple conditional path connects a noise sample $z$ and a data sample $x_1$.

Use linear interpolation:

$$
x_t = (1-t)z + tx_1.
$$

The target velocity is:

$$
u_t = \frac{d x_t}{dt}=x_1-z.
$$

The training objective is:

$$
\mathcal{L}(\theta)
=
\mathbb{E}_{t,z,x_1}
\left[
\|v_\theta(x_t,t)-u_t\|^2
\right].
$$

The target vector tells the model how to move along the path.

<Proof title="Target velocity for a linear path">
Start with the linear path:

$$
x_t = (1-t)z + tx_1.
$$

Differentiate with respect to $t$:

$$
\frac{dx_t}{dt}
=
-z+x_1.
$$

Thus:

$$
u_t=x_1-z.
$$

The velocity is constant along this conditional path.

The learned vector field averages these conditional velocities at each location and time.
</Proof>

## Sampling

After training, sampling solves:

$$
x_{t+\Delta t}
\approx
x_t+\Delta t\,v_\theta(x_t,t).
$$

Euler steps are simple but can need many function calls.

Higher-order ODE solvers can improve accuracy.

The number of solver steps controls a speed and quality tradeoff.

## Relation to diffusion

The probability flow ODE of a diffusion model is also an ODE over probability paths.

Flow matching often trains the vector field directly.

Diffusion models often train a score or noise predictor first.

Both methods can transform a simple base distribution into data.

See <a href="/learn/generative-modeling/diffusion-sde">Diffusion Forward and Reverse SDE</a> for the diffusion ODE view.

## Code example

```python
import torch

def sample_euler(x, times, velocity_model):
    for t0, t1 in zip(times[:-1], times[1:]):
        dt = t1 - t0
        t = torch.full((x.shape[0],), t0, device=x.device)
        v = velocity_model(x, t)
        x = x + dt * v
    return x
```

## Common mistakes

Do not confuse the vector field with a density.

Do not assume the path must be linear.

Do not use too few ODE steps without checking sample quality.
